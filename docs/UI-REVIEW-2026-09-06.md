# UI/UX review — 2026-09-06

A component-by-component review of the application against the
[`ui-ux-pro-max`](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill) skill's 119 UX
guidelines and its pre-delivery checklist, followed by the fixes the review pointed at. This
is the record of what was checked, what was found, what was changed, and what was deliberately
left alone. `CLAUDE.md` §10b carries the rules that came out of it; §18 has the changelog entry.

**Scope:** every shared component in `src/components/`, the shell, the sign-in and invitation
screens, and the token layer in `globals.css`. **No schema, RLS, capability, policy, route or
business rule changed.** 1104 unit tests, unchanged in count. The gallery and the two public
screens were measured in a real browser, at five widths, in both themes.

## 1. Method

1. The skill was cloned and its searchable data run against this product's shape — a
   commercial laundry operations app used on a counter tablet and a driver's phone. Its
   design-system recommendation and its UX guideline search were both consulted; the
   pre-delivery checklist was walked item by item.
2. Each shared component (`ui.tsx`, `form.tsx`, `app-shell.tsx`, `app-nav.tsx`,
   `list-controls.tsx`, `overlay.tsx`, `global-search.tsx`, `user-menu.tsx`,
   `notification-bell.tsx`) was read against the checklist, and every finding was classified
   as **pass**, **fixed**, or **deferred with a reason**.
3. Fixes went into the token layer or the shared component wherever one existed, so every
   screen inherits them — the same discipline the 2026-08-16 re-skin set. No call site was
   restyled by hand.
4. The result was **measured, not eyeballed**: a Playwright harness against `next start`
   over `/design-preview` and `/login`, and a second script that removes each new rule and
   confirms the harness reports the failure. A check that cannot fail is not a check.

## 2. The two decisions the skill argued for and this app refused

The skill's design-system search recommends, for an operations app of this kind, a navy
palette with Inter for body copy and Calistoga for display. Both were considered and
**neither was adopted**, and the reasons are the durable part of this review.

- **The palette stays YSM Hub's "paper and ink with accent."** `CLAUDE.md` §10b records that
  this app and `ysm-prog/ysm-hub` share one design language so the two read as one company's
  software, and every token was pinned to YSM's exact bytes. A navy re-skin would make this the
  odd one out for no functional gain. The palette already clears WCAG AA in both themes — the
  dark theme was contrast-checked colour by colour on 2026-08-16 and again on 2026-08-24 — so
  the checklist's 4.5:1 item passes as it stands.
- **The fonts stay Instrument Sans / Instrument Serif / JetBrains Mono.** The only functional
  question a font swap could answer is whether digits line up in a column of money, and that
  was checked rather than assumed: the Instrument Sans latin subset shipped by `next/font`
  carries `tnum` and `pnum` OpenType features, digits are proportional by default (about a 4px
  spread across 0–9 at 15px), and Tailwind's `tabular-nums` utility engages `tnum` cleanly. So
  a column that needs aligned figures can have them without changing typeface. Inter would
  have bought nothing that this face does not already offer.

Sharing a language with a sibling product is worth more than matching a generic
recommendation, and both refusals are recorded so the next review does not re-run the same
argument.

## 3. Findings

| 2 | Visible feedback on press, not only hover | **Fixed** | Four of six `Button` variants changed on hover and did nothing on press — on a touch screen, where there is no hover, that is no feedback at all. | 3 | Loading feedback on submit | **Fixed** | `SubmitButton` disabled on pending and said nothing. It now shows a spinner before the label and carries `aria-busy`, so a slow save is visibly in flight. |

## 4. Deferred, with reasons

- ~~**Nine files still carry arbitrary `text-[12.5px]` / `text-[13px]` / `text-[17px]` sizes**~~
  **Done in the third pass, same day.** All 23 sites moved onto the scale: 12.5px and 13px to
  `text-sm`, 17px to `text-lg`. The import screen turned out to be the real finding under that
  count — it carried two hand-rolled square buttons at 36px with `hover:opacity-90`, a
  Plantline-era `border-l-[5px]` callout, and 12.5px throughout: the one screen the 2026-08-13
  and 2026-08-16 sweeps never reached. It uses `Button` and `Notice` now.
- **An error summary at the top of a long form** (the checklist's "summarise validation errors
  above the fold") is not built. This app rejects a post by redirecting with one flash message
  naming the box (§2, `lib/messages.ts`), so there is at most one error on screen at a time and a
  summary would list one item. If a form ever validates several fields at once, this is the
  pattern to reach for.
- **`viewport-fit=cover` is not switched on.** `FormActions` now pads its bottom by
  `env(safe-area-inset-bottom)` so the sticky bar clears a phone's home indicator the moment the
  viewport is set to cover; flipping the meta tag itself changes how every full-bleed surface
  meets the notch and wants a device in hand to check, not a container.

  files, production build.

  `/design-preview` at 320 / 375 / 768 / 1024 / 1440 in light and dark, and `/login` at 375 and
  1440 in light and dark. Every combination clean: 0 console errors, 0 interactive targets under
  36px, 0 enabled buttons without a pointer cursor, 0 disabled buttons without `not-allowed`, all
  27 selects carrying the theme's chevron colour, `scroll-padding-top` resolving to 80px, 32
  status-badge dots rendered, the password toggle 36×36 and switching the input type both ways,
  the sign-in copy reading Adelaide, and the measured transition duration 0.16s.

  `select.select-chevron{background-image:none}` and `html{scroll-padding-top:0}` and the harness

- **Screenshots** reviewed at 1440 light and 375 dark: badge dots present, the password eye in
  the box, nothing clipped.

**Not verified behind the auth gate.** This container has no Supabase credentials, so no

## 6. Second pass, the same day: depth and motion

The owner's response to the first pass: *"all pages look very flat … add some animation and 3D
so it should look elegant."* A fair reading. The first pass fixed what was **wrong**; it did
not touch what was **dull**, and the paper-and-ink language had been carried as flatness rather
than as quiet. This pass adds an elevation and motion layer on top of the same palette and
fonts — nothing in §2 moves.

**Principles, so the next person adds to it rather than fighting it:**

- **Depth is light, not colour.** A card is a sheet of paper resting on the page: a faint
  highlight along its top edge, a whisper of gradient, and a layered shadow under it. In dark
  the highlight does the work, because there is no paper for a shadow to fall on.
- **Motion is opacity and transform only** — the two properties a phone composites for free —
  and everything collapses under `prefers-reduced-motion`. Arrival motion is short and once;
  ambient motion exists on exactly one screen, the sign-in panel, where nobody is working.
- **A control answers before it is pressed and again when it is.** Hover lifts; press pushes
  in. Hover is gated on `(hover: hover)` so a phone never leaves a card stuck lifted after a tap.

| Where | What changed |
|---|---|
| Shadow tokens | Every `--shadow-*` reads its colour from `--shadow-ink` and its density from `--shadow-k`, set per theme: ink at 1× in light, black at 2.5× in dark, because an ink shadow that reads on paper vanishes on `#141412`. New `--shadow-card`, `--shadow-card-hover`, `--shadow-raised`, `--shadow-raised-hover`, `--shadow-glow`. |
| `surface-card` | `Card`, `FormSection` and `Stat`: top-edge highlight, faint gradient, layered card shadow. |
| `raised` | Primary and danger buttons: a sheen across the top half, a light edge, a shadow that grows on hover; pressing removes the sheen and turns the shadow inward. |
| `lift` | A `Stat` that is a link and every quick-action card rise 2px under the pointer with the hover shadow, and settle back on press. Secondary buttons lift 1px. |
| `page-enter` | On `<main>`: the header and cards of every screen rise into place 50ms apart on each navigation, capped at 250ms. `backwards` fill so no transform lingers to capture a fixed descendant. |
| `stagger-in` / `animate-rise` / `animate-float` | The same sequence for any list; one thing; and the two soft shapes on the sign-in panel drifting on a ten-second cycle. |
| Shell | A two-pixel gradient hairline of brand colour along the top of the header; the brand mark is a lit teal tile with the brand in its shadow; the active rail row carries a shadow and a hover row nudges right. |
| Quick actions | The icon tile fills with the brand gradient on hover of the card (`group-hover`). |
| Inputs | Focus adds a soft glow (`--shadow-glow`) around the existing ring. |
| Overlay and account menu | The rise keyframe now carries a touch of scale, so a panel settles rather than sliding. |

**Measured**, with a second harness (`depth.mjs`) over the gallery at 320/375/768/1024/1440 and
the sign-in page at 375/1440, both themes: the card carries a shadow and a gradient, the primary
button carries a sheen at rest and loses it on `mousedown`, the lifting stat is `matrix(1,0,0,1,
0,-2)` under the pointer and identity at rest, the stagger delays read 0s / 0.05s / 0.1s, the two
floating shapes run `es-float`, and the form's rise ends at opacity 1. No console errors, no
target under 36px, no new document overflow. The first-pass harness was re-run on the same build
and is still clean. **The first run of this harness reported every section absent — the first
pass's `next start` was still holding port 3000 and serving the old build.** The trap this file
records on 2026-08-25 and 2026-08-26, and the reason the harness checks the section exists before
measuring anything.

**Deliberately not done**: parallax, 3D transforms on cards, skeleton shimmer on every load, and
per-row entrance on tables. Each is motion a person on a loading dock has to wait through, and a
table of two hundred rows animating in is a table that arrives late.
